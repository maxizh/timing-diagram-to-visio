## 1. 一句话定位

给芯片设计工程师的**小而专**的 AI 画图工具：用自然语言、鼠标点选或截图输入，直接产出**可进 Visio 编辑的矢量图**。

明确**不做**大而全的 EDA / 原理图工具 —— 需求探索阶段第一版方案就是被这个否掉的。

---

## 2. 目标用户与痛点

- **用户**：芯片设计工程师（RTL / 验证 / 数字前端）
- **痛点**：画 Visio 图（时序图、流程图、状态机、架构图）纯手工、极其耗时
- **现状**：先手写草稿 → 再在 Visio 里一笔一笔描成规整图形，两遍工
- **期望**：草稿阶段就随便画（白纸手绘的手感），但**产出直接就是规整的 Visio 图**

## 4. 功能需求详述

### 4.1 输入方式（三条路径，all-in-one 的核心）

| 路径 | 描述 | 状态 |
|---|---|---|
| **A. 自然语言** | 一句话描述协议/时序 → 出图。例："SPI mode 0 传输 0xA5，CS 低有效 8 个时钟周期" | ✅ |
| **B. 图片（截图/拖拽/粘贴/拍照）** | 粘贴 Visio 草稿、Verdi 波形截图、datasheet 时序图 → AI Vision 识别 → 出图 | ✅ |
| **C. 鼠标点选 from→to** | 纯鼠标交互，不写任何描述，像在白纸上画 | ❌ 待做 |

**B 路径的两个具名场景：**
- **B1 · Verdi 波形截图**：仿真调试时直接截 Verdi 的 wave 窗口粘进来
- **B2 · 规则化程度极高的图片**：datasheet 里的时序图、手绘但结构清晰的框图（B1 是 B2 的特例）

### 4.2 图形类型

| 类型 | 状态 |
|---|---|
| **waveform 时序图** | ✅ 已跑通（P0） |
| 流程图 | ❌ 待做 |
| 状态机 | ❌ 待做 |
| 架构图 | ❌ 待做 |

### 4.3 输出规格

- **格式**：SVG（纯矢量，Visio 2024+ 用 `File → Open` 直接打开；需拆形状时 `Ungroup`）
- **风格**：白底黑线，**垂直直角电平跳变**（原厂 / datasheet 时序图风格），信号名深蓝
- **可编辑**：输出为纯 `<path>` / `<text>` 元素，不带位图
- **同时保留中间表示**（WaveJSON），方便二次修改

### 4.4 质量要求 —「一模一样」（R18，硬约束）

这是**验收红线**，不是"看着差不多就行"：

- 输出波形必须与输入图片**逐信号、逐 bit 拓扑等效**
- 高/低电平序列必须完全一致
- 禁止任何"把电平替换成别的视觉元素"的行为
- 验证方式：**把 wave 字符串按位还原成 bit 序列再和原图对照**，不靠肉眼

## 5. 交付与工程规范

| 规范 | 内容 |
|---|---|
| **单 HTML 交付** | 所有外部资源（图片 / CSS / JS）**必须 base64 内嵌或走 CDN**，禁止同目录相对路径 |
| 原因 | WorkBuddy 预览面板是**单文件服务**（`http://127.0.0.1:.../static-html/<hash>/<file>`），不映射同目录资源，相对路径全部 404 |
| **交付前自测** | 必须用真实浏览器（或 agent-browser）打开看一眼再交付 |
| **隐私** | API Key 只在本地浏览器发起调用，不上传任何服务器 |
| 依赖偏好 | 渲染器走**本地零依赖**，不依赖外部在线服务（避免网络抖动 / 服务不可用） |

## 6. 技术方案与已确立决策

### 6.1 主链路

```
图片/自然语言
   ↓  AI Vision / Claude
WaveJSON（中间表示）
   ↓  scripts/wavejson2svg.py（自研渲染器）
SVG（直角方波，白底黑线）
   ↓  Visio File → Open
.vsdx（可编辑）
```

### 6.2 为什么自研渲染器而不用官方 WaveDrom

| 对比项 | 官方 WaveDrom | 自研 `wavejson2svg.py` |
|---|---|---|
| 电平过渡 | 斜边梯形 | **垂直直角**（原厂风格） |
| 连续同电平 | 每个字符边界画多余转折 → 尖刺 | **自动合并，无多余记号** |
| 单 bit 宽度 | 需 4 字符才像方波（图变 1840×212 极扁） | **2 字符即可**（654×316，比例接近原图） |
| 依赖 | CDN / 在线服务 | **本地零依赖，离线可用** |
| Visio | 可用 | 白底黑线纯 path/text，直接 `File→Open` |

### 6.3 数据对齐约定

**1 个 bit = 2 个字符**，这样 1 个数据位恰好对齐 1 个 SCLK 周期。

- CPOL=0（Mode 0/1，空闲低）：每周期 `"01"`
- CPOL=1（Mode 2/3，空闲高）：每周期 `"10"`
- 首尾各留 2 字符空闲电平

示例（SPI Mode 0，MOSI=0x5A，MISO=0xC3，全部 20 字符对齐）：

```
CS_n   11000000000000000011
SCLK   00010101010101010100
MOSI   00001100111100110000
MISO   00111100000000111100
```

### 6.4 为什么"手绘 → 标准框图"这么难（R9 的答复）

用户手绘的笔迹是**连续自由曲线**，而标准框图是**离散符号 + 拓扑关系**。中间要跨三步：

1. **笔画分割** —— 把连续笔迹切成"这一段是个矩形""这一段是根箭头"
2. **符号识别** —— 判断切出来的东西对应哪个标准图形（判断框？处理框？）
3. **拓扑重建** —— 推断节点之间的连接关系和层级

第 3 步是真正的难点：图上没写"谁连谁"，只能靠箭头位置和重叠关系猜，**没有确定解**。
而 waveform 天然是**离散的**（每个时钟周期一个采样点，电平只有 0/1），
识别难度低一个数量级 —— 这就是当时建议"先只做 waveform"的原因，实践证明对了。

## 7. 已知坑（血泪清单，务必遵守）

### 坑 1 · `2-9` 是数据块，不是电平 ★最致命

WaveDrom 里 `2`…`9` 渲染成**彩色数据槽方块**，跟高低电平毫无关系。

- 单 bit 数据线（MOSI / MISO / DQ / DIN / DOUT / TX / RX）**只能用 `0` / `1`**
- `2-9` 只留给**真正的并行总线**（如 D[7:0] 一周期传一个字节）
- 用错的后果：数据线高/低电平**整段消失、变成一排方块**，图与原图完全不等效（这就是 R18 报的 bug）

```jsonc
// ❌ 错：数据线全变成数据块
{"name": "MOSI", "wave": "x23456789x", "data": ["D7=0", "D6=1", ...]}

// ✅ 对：每 bit 2 字符的真实电平
{"name": "MOSI", "wave": "00001100111100110000"}
```

### 坑 2 · 不要用 `.` 或 `x` 开头

没有前值可延续时会渲染成**未定义态的斜线阴影**。开头写实 `0`（或实际空闲电平）。

### 坑 3 · 官方 WaveDrom 的边界艺术符号

`"0000"` 这种显式重复字符，WaveDrom 会在**每个字符边界画一个多余转折** ——
`CS_n` 这种全程恒定的低电平会变成**一排尖刺**。
→ 用 `scripts/wavejson2svg.py` 规避（相邻同电平自动合并）。

### 坑 4 · `svg.wavedrom.com` 的接口参数格式

`https://svg.wavedrom.com/{code}/` 里的 `{code}` 是 **URL 编码的原始 JSON**，
**不是 base64**。传 base64 会返回一个 `{"lineNumber":1,"columnNumber":1}` 的错误 SVG。

### 坑 5 · 单 HTML 的资源路径

见 §5。必须 base64 内嵌。

### 坑 6 · 别被"风格差异"糊弄

用户说"一模一样"时，指的是**拓扑 / 电平序列等效**。
不能用"这是 WaveDrom 的渲染风格"来搪塞 —— 该换渲染器就换。

## 10. 验收标准（Definition of Done）

一条 waveform 链路算完成，需同时满足：

1. 输入图片能正确识别，wave 字段严格等长
2. **逐 bit 还原校验通过**（`wave[2:18:2]` 还原的 bit 序列与输入一致）
3. 渲染结果是**直角方波**，无多余尖刺、无数据块误用
4. 导出的 SVG 在真实浏览器中渲染无异常
5. 交付的 HTML（如有）所有资源已 base64 内嵌
6. Visio 2024+ 能 `File → Open` 打开并 `Ungroup`
