## 一、这次试用的净收获：修掉一个PNG 躲得过、必踩的 bug

### Bug：`load_dark()` 未归一化灰度 → **JPEG 输入必然失败**

```python
# 修前
im = mpimg.imread(path)
gray = im[..., :3].mean(axis=2)      # 值域取决于格式！
return gray, gray < DARK# DARK = 0.45，是 0-1 尺度
```

`matplotlib.image.imread` 的返回值**取决于文件格式**：

| 输入 | 返回值域 | `gray < 0.45` 的后果 |
|---|---|---|
| 8-bit PNG | **0.0 ~ 1.0** | 正常 |
| **JPEG** | **0.0 ~ 255.0** | **只剩「值恰为 0」的像素成立** |

实测（JPEG 输入）：

```
gray.dtype/range : float64 0.0 255.0     ← 应为 0.0~1.0
深色像素占比     : 0.0022  （正常应约0.04）
wave_span       : [0, 1919]   ← 退回整幅图
标签列范围      : x < 0        → 空
报错            : 只找到 0 个行标签
```

**为什么自检一直是绿的**：基准图 `assets/test-input-spi.png` 是 PNG，恰好落在 0-1 区间，
bug 被完美掩盖。**直到拿真实 JPEG 截图试才暴露** —— 这正是「真实需求试用」的价值，
纯自检永远测不出输入格式相关的问题。

### 修法

在读进来的当场按实际值域归一化，**判据常数一律不动**（`pdf_trace.DARK ≡ auto_trace.DARK`
是跨模块硬约定，自检 [10] 守着）：

```python
mx = float(gray.max())
if mx > 1.0:
    gray = gray / 255.0
return gray, gray < DARK
```

**回归验证**：自检 **74 项全过**（PNG 路径行为完全不变）。

### L1 几何解析 —— 分行成功，电平提取失败

```bash

```

修复后逐行诊断（`level` 行的双轨检测）：

```
行       y区间      长横段数   双轨    原因
 0   [59,81]15      0    CK_c/CK_t 差分时钟，非方波
 1  [108,130]       14      0    CK_t 差分时钟
 2  [186,209]        0      0    C[7:0] 是 READ 彩色数据格，无横线
 3  [371,393]        0      0    READ 彩色块
 4  [420,442]        3      0    WDQS_c 灰底+彩色混叠
 5  [475,497]        0      0    WDQS_t

```

用 `--rows` 手工指定行类型兜底（`level,level,...,bus,bus,bus`）**仍然失败**——
因为前8 行的波形本身就不是「双轨电平线」（差分正弦 / 彩色数据格）。

### 结论：⛔ 不适用自动转换

**工具行为是正确的**——明确报错、不硬凑假电平、不输出垃圾。这符合设计原则
「拿不准时报错 ≫ 静默丢数据」。

**四条边界特征这张图全中**：

| 特征 | 本图实际情况 |
|---|---|
| 彩色状态块编码 | READ 块有橙/黄/淡青/蓝四色；DBI 状态行有橙/黄/绿/青多色 |
| 每时钟 4 字符 | C[7:0] 与 D0..D7 格间距 = 半个时钟 |
| T 标号跳号 | T0→T1→**T8**→T9…T12→**T17**→T18…T23（两处断口） |
| 无独立时钟行可用 | CK_c/CK_t 是差分正弦，不是直角方波 |

### 正确做法（与 2026-09-21 一致）

**人工反解 + 几何测量后重绘**，并对用户如实说明「这是重绘不是自动读图」。
现成范例：`test-cases/real-datasheets/build_lpddr_fig15.py`（含全部像素测量依据）
产物：`lpddr4-fig15-*.svg` / `.json` / 对照 HTML / 四陷阱标注图
