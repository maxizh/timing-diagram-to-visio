DQM 的「驼峰」到底是什么 —— ISSI IS42S16400J p54

我把 DQM 那一行放大标出来了。「驼峰」= 那一排窄窄的、顶平的灰梯形 （图里红虚线标出的就是它们的中心）。它和左边那块盖满两个整槽的大灰带 不是同一种东西。

为什么这事要紧：如果驼峰也算 DON'T CARE，DQM 就会从 xxxx0000000000000000 变成一长串 x。所以得先弄清它到底是不是「值不确定」。
蓝实线 = 位槽边界（两条 T 线中点） 蓝虚线 + T0..T9 = 厂商自己的标号竖线 = 时钟上升沿 红虚线 = 驼峰中心 = 时钟下降沿 红框 = 大灰带 绿虚线 = CKE 的驼峰边沿 绿格 = 输出 0/1 红格 = 输出 x

更正一下我上一轮的说法：当时写「驼峰落在 bounds[1..8]」——位置（bounds）没说错， 但索引数错了，实测是 bounds[3..10] 共 8 个；而且 bounds 是下降沿， 厂商自己的 T0..T9 竖线才在上升沿上。结论不变。

逐槽覆盖率与输出

判据：一个位槽里灰底列占比 ≥ 0.60 才算整槽 DON'T CARE。实测两簇分得很开 —— 被大灰带盖满的槽 0/1 是 0.95 / 1.00， 其余槽只有 0.29~0.47（那是驼峰伸进来的零头）。

结论：驼峰不该变成 x，现在的输出是对的

大灰带（盖满整槽、底宽一个整周期以上）＝ 逻辑上的 DON'T CARE → 输出 xx；
驼峰（底宽半个周期、压在时钟下降沿上）＝ 厂商标的 tCMS/tCMH 之类的建立/保持窗， 线才是值 → DQM 在这张图里始终走那条低电平线 → 输出 0。

结果 xxxx0000000000000000 = 前 2 槽 DON'T CARE + 后 8 槽低，与原图一致。 我原来把它列成「待定夺」是读图不够；CKE 那条对照把它证死了，判据不用改。
